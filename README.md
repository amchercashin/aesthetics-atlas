# Атлас эстетик

Навигатор по визуальным стилям, которые придумали люди: от наскальной живописи до vaporwave, weirdcore и эстетик 2026 года.
153 карточки: родословная, хронология, главные работы и ссылки для самостоятельного изучения.

Атлас выборочный и неоднородный. Он сочетает традиции, периоды, движения, техники, дизайн-подходы и интернет-тренды, и тип каждой карточки указан. Европа и XX век описаны подробнее остальных регионов: см. [матрицу покрытия](docs/coverage.md) и [план расширения](docs/expansion-proposal.md). Связи между стилями — в основном редакционная схема. Что сверено с источниками, а что нет, видно на каждой странице и в [реестре аудита](docs/content-audit.md).

- **Карта**: родословное древо на оси времени. Точка — начало стиля; длительность не рисуется (годы — в подписи и у выбранного стиля). Раскладка оставляет место под подпись каждого стиля на просторном обзоре, поэтому карта больше экрана: её двигают, а миникарта в углу показывает, где вы; «Вся история» вписывает всё целиком. Ветви обходят подписи, толщина линии — сколько стилей из неё выросло, далёкие связи показаны парными отростками. Клик по стилю — ближайшие связи крупным планом (тип связи подписан словом, дальние концы — метками на краю экрана), «Вся родословная» — цепочка до истоков. Клик по линии объясняет связь. Фильтр по области и типу карточки, навигатор эпох. Отдельный слой — визуальные сопоставления.
- **Хронология**: двенадцать эпох по порядку, каждая со своим пигментом.
- **Каталог**: все стили сеткой работ с фильтрами по области, типу карточки и эпохе.
- **Зал стиля**: главная работа с этикеткой, признаки, палитра, родословная со статусами связей, источники утверждений, ссылки.
- **Поиск** (`/` или `⌘K`): по названию, художнику или году.

Сайт статический: HTML, CSS и ES-модули без фреймворков и сборки кода. Собираются только данные.

## Структура

```
content/            исходные данные (YAML), их редактируют руками
  eras.yaml         эпохи
  styles/*.yaml     карточки, по файлу на эпоху
  sources.yaml      источники утверждений (по id)
  resources.yaml    раздел «Копать дальше»
data/atlas.json     СГЕНЕРИРОВАН из content/ (не редактировать)
docs/               реестр аудита, матрица покрытия (генерируется), план расширения
js/, css/           сайт
scripts/            сборка данных и проверки
test/               юнит-тесты
```

## Карточка

Обязательные поля: `id`, `name`, `orig`, `start` / `end`, `era`, `domain`, `tier`, `parents` (или `root: true` / `origin: unknown`), `summary`, `description`, `traits`, `example`, ссылки.

**Что описывает карточка**

- `kind` — тип: `overview`, `tradition`, `period`, `movement`, `school`, `technique`, `design-system`, `internet-aesthetic`, `trend`. Можно указать основной и вторичный тип; пояснение — в `kindNote`.
- `scopeNote` — что карточка охватывает и чего не охватывает.
- `aliases` — варианты названия. `searchKeywords` — поисковые ассоциации: имена, предметы, соседние термины.
- `medium` — медиум, независимо от `domain`. Сейчас заполнен у пилотных карточек.

**Даты**

- `start` / `end` — календарные годы, до н. э. — отрицательные. `dates` — строка для показа.
- `dateKind` — что значат даты: `archaeological`, `period`, `institution`, `practice`, `popularity`.
- `approx: true` — дата приблизительная. `dateNote` — пояснение.
- Возраст «тыс. лет назад» переводится в календарный год приблизительно, а правило пересчёта записывается в `dateNote`.
- `end: null` значит «продолжается»; если конец неизвестен, укажите `endKind: unknown`.
- `termAttested: { year, source }` — когда документировано само слово, если это не совпадает с началом практики.
- `revivals` — поздние возвращения.

**Связи**

- `parents: [{ id, type, status, note, sources }]`. Тип — `evolved | influence | reaction | revival`.
- `status: verified` требует `sources`. Без статуса связь считается `unverified` — это гипотеза редакции.
- Первый родитель задаёт линию на карте, но не означает доказанную «главную линию».
- `origin: unknown` — происхождение не установлено. Не выдумывайте родителя ради сборки.
- `compare: [{ id, note }]` — визуальное сопоставление: сходство, а не происхождение. Объявляется на одной стороне, на сайте видно с обеих. В генеалогию и проверку циклов не входит.

**Источники и проверка**

- `evidence: [{ claim, field, source }]` — какое утверждение каким источником подтверждено. Источники лежат в `content/sources.yaml` с полями `id`, `title`, `url`, `publisher`, `sourceType`, `checked`, `note`; в `note` записано, что именно источник подтверждает.
- `review: { status: partial | reviewed, date, note }` — карточка сверена. Без `review` карточка считается черновой, и это видно на сайте.
- Ссылки `links` и автоматические ссылки на Википедию и Commons — материалы для чтения, а не подтверждение текста.

**Изображения**

- `example` и `gallery`: `file` — точное имя файла на Wikimedia. Файлы, которые лежат только в английской Википедии, пишутся с префиксом `enwiki:`.
- `role`: `work` по умолчанию, `precursor`, `revival`, `reconstruction`, `illustration`, `portrait`. Всё, кроме `work`, подписывается на сайте.
- `whyRepresentative` — что в работе видно из признаков стиля.
- `author`, `year`, `place` относятся к произведению. Автор и лицензия фотографии берутся из Commons отдельно.
- `place` — собрание или местонахождение по данным источника на дату проверки. Это не гарантия, что работа сейчас выставлена.
- `rights: { basis, reviewed, note, embed }` — основание использования и оговорки. `embed: false` заменяет картинку ссылкой на страницу файла.

**Палитра**

- Без `palette` сборка извлекает пять цветов из главной иллюстрации и подписывает их «Цвета этого изображения».
- Ручная `palette` — «Редакторская подборка»; основание пишется в `paletteNote`.

Подобрать картинки:

```bash
npm run find -- "запрос"                 # поиск по Commons
npm run find -- --article "Vaporwave"    # картинки статьи en.wikipedia
```

Перед тем как ставить картинку, откройте её и проверьте описание файла: имя файла ничего не доказывает.

## Сборка и проверки

```bash
npm ci
npm run build        # граф, источники, картинки, палитры → data/atlas.json (при ошибках не пишется)
npm test             # шкала, раскладка, поиск, валидатор, перенос полей, проверки контента
npm run check-links  # внешние ссылки (404 — ошибка)
npm run coverage     # docs/coverage.md
```

Валидатор проверяет структуру и согласованность: связи ведут к существующим карточкам, генеалогия без циклов, источники существуют, даты связей не противоречат её типу. Историческую истину и репрезентативность изображения он доказать не может.

## Локальный просмотр

Сайт рассчитан на работу из подпапки, как на GitHub Pages:

```bash
python3 scripts/dev-server.py 8765
```

Затем откройте `http://localhost:8765/aesthetics-atlas/`.

## Публикация

GitHub Pages из ветки `main` (корень). Все пути относительные, роутинг через `#/…`, поэтому дополнительная настройка не нужна. Если карточку разделяют или переименовывают, старый id сохраняют за обзором или записывают в `formerIds` новой карточки: старые ссылки продолжат работать.

## Изображения и права

Изображения загружаются напрямую с Wikimedia Commons и Википедии, под каждым указаны автор снимка или репродукции, лицензия файла и ссылка на его страницу.

Лицензия фотографии относится к снимку. Права на изображённое произведение — здание, скульптуру, плакат — могут принадлежать другим.

Несколько работ XX–XXI века показаны как превью низкого разрешения из английской Википедии. Википедия использует их по собственному обоснованию fair use, и это обоснование не переносится автоматически на атлас: допустимость зависит от конкретного использования и юрисдикции ([Wikipedia: Reusing content](https://en.wikipedia.org/wiki/Wikipedia:Reusing_Wikipedia_content)). Такие изображения помечены «несвободное», а под ними написано, проверено ли основание их использования. Правообладатель может попросить заменить изображение ссылкой через issues.
