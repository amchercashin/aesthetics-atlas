# Программа расширения атласа

Зафиксированы **575 кандидатов**, включая 196 авторских языков и 176 коллективных традиций. Сохранены 180 предложений v1, добавлены 395. Исходный снимок проекта — 153 карточки на ревизии `d3f619b3ca715386a1e271e193e3a5276440adb6`, 14.10.2026.

Статусы программы: **54** записи `merged` (карточки в main), **521** — `candidate`, `prepared` — 0. `prepared` не означает слияние PR или публикацию сайта. [Пилот](../../docs/author-style-pilot.md), [первая региональная порция](../../docs/regional-traditions-batch-01.md), [отчёт второй порции](../../docs/regional-graphics-batch-02.md) и её [рабочий журнал](../batches/02-regional-graphics.json); прочитанные предметные источники перечислены в `verificationSources` и production-реестре `content/sources.yaml`.

Это очередь редакционного исследования. Публикация требует самостоятельного решения по каждой теме. Даты, признаки, представители, изображения и генеалогия не считаются проверенными на основании присутствия записи в очереди.

- [catalog.json](catalog.json) — канонические кандидаты с типом, географией, предложенными признаками, корпусом для отбора, соседями, основаниями и приоритетами. Одна запись занимает одну строку, чтобы последующие решения были видны в небольших diff.
- [sources.json](sources.json) — исходный снимок 72 исследовательских источников и точных пределов поддержки. В этом снимке основной текст прочитан у 38, поисковое извлечение доступно у 33, один — маршрут по коллекции; ссылки есть у 100 кандидатов, у 457 задан только маршрут поиска. Новые проверенные предметные источники добавляются отдельно в `verificationSources` кандидатов и `content/sources.yaml`.
- [relations.json](relations.json) — 55 исторических гипотез, 50 визуальных сопоставлений, 35 предложений контекста. Они не импортируются в историческое дерево.

## Порядок работы

1. Поддержка авторских корпусов, культурных контекстов и раскрываемого уровня карты; пилот из 12 разных случаев.
2. Проверенные тематические партии по 10–20 карточек, сначала P1 (123 темы), затем P2 (429); R (23) требует проверки самостоятельности или полезности узла.
3. Расширение по выявленным пробелам и журнал решений. Число записей не является мерой исторической точности или доказательством полноты.

Для каждого обработанного кандидата сохранять `admissionDecision`. В действующей практике PR партии сливается в той же сессии, поэтому используются три значения: `merged` — карточка есть в `main`: собственная (`productionCardId` — её id) или существующая, в которую вошла тема (`productionCardId` — id той карточки, причина в `decisionNote`); `deferred` или `rejected` — с причиной в `decisionNote`. Значения `prepared` и `published` валидатор допускает, но они не используются. Для `merged` нужны `productionCardId`, `decisionDate`, `decisionNote`, `verificationSources`. Порядок работы по очереди и трекер партий — [программа расширения](../../docs/superpowers/plans/2026-11-13-expansion-program.md). Исследовательская запись остаётся с историей решения. Приоритет не заменяет состояние проверки.

```sh
npm run research:check
```

Команда проверяет структуру очереди, источники и соседства отдельно от production-схемы. При появлении ID кандидата в `content/styles/` требуется явно зафиксировать решение. Она не проверяет историческую истинность, не просматривает изображения и не превращает исследовательские ссылки в источники утверждений карточки.

Работа с программой ведётся поверх [PR аудита №1](https://github.com/amchercashin/aesthetics-atlas/pull/1): он содержит актуальные исправления содержания и поддержку собственных SVG-иллюстраций.
